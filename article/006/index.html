机器人策略可以就是一个 agent 吗？——Agent as Policy（AGP）技术解读

开场：一台没有策略的机器人

桌面上摆着一个六角螺母和一根短立柱。机器人先看顶置相机拍下的画面，再调出腕部相机的深度图，写一段程序算出螺母中心与立柱轴心的偏差，然后给机械臂下发一个末端位姿，让它把螺母套上去。套偏了就退回来，重新算一次，再试。

整个过程里没有一个训练好的策略网络在输出动作。动作是 agent 在运行期算出来、写出来、再发出去的。这就是 2026 年 9 月的论文《Agent as Policy for Robotic Manipulation》要说明的事：通用 agent 可以直接充当机器人的策略，全程不做任务专属或环境专属的训练，模型权重保持不变。

它的成绩单是这样的：八组任务配置里七组成功率不低于 80%，其中五组观察到 100%；同一张表里，每个任务平均要跑二十一到五十四分钟，烧掉五百万到两千两百万个输出 token，花掉七到二十七美元。

这篇文章要回答两个问题：这条路线把哪一层拿掉了？拿掉之后，代价写在哪里？

一、过去怎么做：策略是训练产物

要把这件事说清楚，先看策略在一套具身系统里通常是什么。VLA 的接口是「看当前观测与指令，输出接下来一段动作」，视觉、语言与控制在同一个训练框架里联合优化，策略就是那组参数。行为克隆、离线 RL、扩散策略做法不同，共同点是策略的产出过程发生在训练阶段。

这个前提会牵出一整条工程惯性。数据要采、要标、要混；动作要选一种表示——离散 token、连续回归还是一段 chunk；训练完还要评测，而评测协议本身又决定了下一次该采什么数据。具身智能这三年里大部分工程投入都在这个循环里，它也确实把成功率推了上去。

代价是它把「这一次该怎么做」提前锁进了参数。部署现场出现训练分布里没有的目标绑定、布局或接触条件时，参数不会临时改变主意。前几篇讨论的 RoboICL、WAM、RPent 各自在不同的位置补这个缺口：改上下文、改决策里是否含后果、改执行由谁组织。

部署阶段的改动因此也都围绕参数展开：微调、适配、换数据配方。前面几篇讨论过的 RoboICL 是这条思路的边界形态——它证明了不改参数也能在部署现场调整行为，但动作本身仍然由学出来的生成器给出。

AGP 换了个位置提问题：如果 agent 已经能读图、能写代码、能在失败之后改主意，那策略还需要单独训一个网络吗？

二、拿掉了什么：π 从网络变成一次工具调用

论文的形式化只有一行：

u_k ~ π_θ( · | g, I, H_k, W_k )

等号左边是第 k 步选择的一次工具调用，不是一段动作序列。右边是任务说明与参考材料、带文档的机器人接口、这一步可见的对话与工具结果，以及工作区里的文件；参数在整个执行过程中不变。

这行公式看起来像标准的策略定义，含义却完全不同：这里的 π 不是训练出来的函数，而是 agent 的下一步决定。 它可以是「拍一张腕部相机图像」，也可以是「运行我刚写的这段程序」——而那段程序会直接算出目标位姿并下发指令。

把这一步讲具体一点，一次典型的工具调用会做四件事：读一张刚拍的图、在程序里估计某个几何量、由此算出目标位姿或关节角、把结果提交给机器人接口。动作不是被「预测」出来的，是被「算」出来的。 这也是它与「LLM 规划器 + 底层原语」那类系统的分界：后者的规划器输出的是子目标或调用指令，真正的动作仍由别人负责；这里连「算目标位姿」这一步都在 agent 手里。

一个容易被略过的设定：任务的类型第一次引入时，会有另一个 coding agent 先准备一份可复用的任务定义，写明目标、参考材料、约束、允许的变化、完成条件、接口访问规则、预算与报告要求；之后的实例由执行 agent 带着这份定义启动。所以「零样本」的准确含义是执行阶段不做新训练，不等于系统里没有任何准备环节。

编辑部判断：这条路线值得注意的地方不在「用 LLM 做规划」——那是更早就有的思路。变化在执行权限的归属：过去的规划器产出计划或子目标，动作由策略落地；这里 agent 自己持有下发运动指令的权限，它同时是规划者和执行者。本文把这个位置称为 policy-ownership interface：谁拥有「发出动作」这件事。

图 1：左边是训练产物式的策略，动作由参数算出；右边 agent 直接持有下发动作的权限，动作在运行期被计算、写出并发出。两者共用同一台机器人，差别在于「谁拥有发出动作这件事」。图：青稞社区绘制，编辑部解释框架。

三、系统怎么搭：双向接口、运行期程序与反馈闭环

这套系统由三部分撑起来，论文第 3 节写得很具体。

机器人接口是双向的。 上行方向，机器人给 agent 两类信息：相机观测（顶置视图与带对齐深度的腕部视图）以及本体状态（电机反馈的关节位置、由正运动学算出的末端位姿，以及每次运动后返回的更新状态与目标误差）。下行方向，agent 发两类请求：观测请求与动作请求。动作请求里，agent 可以自己选择给关节目标，还是给末端位姿目标；后者描述夹爪放在哪里、朝向如何。末端目标由 Mink 求逆运动学变成关节目标，再生成受工作空间与运动限制约束的关节轨迹，用电机反馈跟踪。

agent 在运行期写程序。 它在执行过程中用 Python 处理观测：估计物体位置、由深度换算夹爪目标位姿、把结果通过接口下发。论文附录专门统计了这些记录下来的程序在几何估计、视觉处理与机器人调用组合上的分布。

每次动作之后都有一轮修正。 agent 用运动反馈与新观测更新估计与后续动作：插入失败就重新估计对齐、换一种接近方式。抓取姿态、动作顺序、观测时机与恢复策略都在这个循环里被决定，直到它报告完成或触及预算。

控制侧的几条细节决定了这个循环在物理上能不能转起来。机械臂在两次请求之间会保持姿态，agent 可以在这段时间里推理下一步；两条臂的动作各自按顺序执行，但对不同臂的指令可以并行；末端目标由逆运动学解算后会经过工作空间与运动限制的裁剪。agent 不需要写轨迹规划器，但它要负责决定「目标在哪里」。

三者合起来是一个闭环：看、算、动、看结果、改。这个环里没有一处需要「训练一个策略」才能转动。

被这段描述压在底下的还有一个前提：接口必须有文档。 每次试次开始时，agent 拿到的是任务说明、接口文档、参考材料与一个可写的目录；它靠读文档知道有哪些调用、每个调用的参数是什么意思、返回值里哪个是目标误差，而没有机会从零样本试错里猜出接口语义。换一台机械臂、换一套控制栈，这份文档就要重写一遍——这条路线的可迁移性，一半压在模型能力上，另一半压在这里。

图 2：上行是相机观测与本体状态，下行是观测请求与动作请求；agent 在中间写程序算目标，再按返回的目标误差与新观测修正下一步。图：青稞社区绘制。

四、任务与协议：四组任务、预算与判定

硬件是六自由度 I2RT YAM 机械臂配平行夹爪。腕部 Intel RealSense D405 提供 640×360 的对齐 RGB-D，固定顶置的 Logitech BRIO 提供 1920×1080 图像，两者都是 30 fps，agent 按需请求观测。双臂折毛巾用两台 arm server，共用一套坐标系，协同方式由 agent 选择。默认配置是 GPT-6 Astra 高思考档。

任务按能力维度分成四组，指令形式各不相同：

  • 长时程推理：从人手演示视频装配四对零件（带棱套筒与圆底座、六角螺母与短立柱、光滑套筒与阶梯圆柱、长销与空心管）；从目标图像搭积木，三种配置分别是金字塔、双塔与六块塔。
  • 动作多样性：语言指令下把六个随机摆放的骰子翻到指定朝上的面；语言指令下把土豆掷进目标。
  • 物体多样性：视频指令下折毛巾，演示方式分顺序（先后折两端）与同步（两端一起向内折）。

论文说明了为什么不用常规的抓放任务：把物体放进碗里这类任务对这个系统而言挑战不足，因此选了更吃力的四组。装配的四对零件由三维打印件构成，零件模型取自一个已有数据集；装配顺序、参考视频与带时间戳的文字指引在各方法之间共享。

判定标准也写得比较细，这决定了成功数怎么算。折毛巾要求两次向内折都完成、边缘大致对齐，允许有轻微褶皱，最后放在桌面的位置不限；掷骰子要求六个朝上的面全部符合指令；掷土豆要求落进目标。「成功」在这些任务上有明确定义，但定义的具体松紧由作者设定，这也是这类真机研究难以横向比较的原因之一。

协议部分有三条必须一起写出来的设定。第一，试次使用预定义的初始场景与固定的预算——时间、观测请求数与动作请求数都有上限，允许在预算内恢复；一旦重置或有人员介入，该次自主试次即终止。第二，成功由物理结果与录制视频按预先定义的标准判定。第三，时间统计从任务下发开始到最终物理验证结束，只统计成功的试次，并且包含动作复核与结果验证；token 统计同样只覆盖成功试次，含推理 token 与重试；成本按 Standard API 费率计算，并通过缓存输入价计入缓存命中。

最后这两条会直接影响后面的数字怎么读：表里记的是「这件事从头到尾花了多久」，而不是「机器人动了多久」。

还有一条藏在预算里：时间与请求次数都有上限，触及上限即算这一次没有完成，并且用掉的开销照付。所以成功率读起来是「在给定预算内达成任务的比例」。把预算放宽，成功率会变高、单次成本会变贵；收紧则相反。表里的每个数字都绑在这套预算上，换一套预算，这张表就要重算。

论文自己的汇总口径是：八组配置里七组成功率不低于 80%，其中五组观察到 100%。摘要用的是另一种表达——在装配、搭积木与掷骰子三类任务上，每个评测配置至少十次中成功八次，这与 4/5 是同一个数。

括号里的区间是论文给出的最小与最大值，它比平均值更值得看。四对装配的平均 54.3 分钟，最短 38.6 分钟、最长 78.2 分钟；积木六块塔最短 17.3 分钟、最长 55.0 分钟。同一套方法在同一个任务上的耗时能差出三倍，而成功数只有 5 次，区间本身也很不平稳。

读这类数字还要注意 n/N 的含义。它统计的是一次完整试次里任务是否达成，而不是中间步骤的正确率；装配任务另外报告了「装对了几对」的比例，但主表用的是整体成败。也正因为只统计成败，5 次试次里的一次波动就是 20 个百分点——这个量级下，成功率之间的差别很难以统计口径去比较。

两处失败值得单独指出。折毛巾同步版是全文最低的 3/5，作者把原因归到「协同操纵可变形材料的动态过程」；六块塔 4/5，作者把它作为任务复杂度上升导致开销增加的例子。没有更细的失败模式分解，这一点后面还会提到。

把这张表放回它要支撑的论点上看，会更清楚它的边界在哪。论文要说明的是「不训练也能做」——从「没有任何任务专属训练」到「七组不低于八成」，这个跨越本身是有信息量的。但没有任何一组数字是在与训练型方法的对照下取得的，所以它支撑的是「可行」，还支撑不到「更优」。这两句话经常被合在一起说，读的时候要拆开。

换成直观的量级：装配四对零件要烧掉两千两百多万个输出 token、花二十七美元；折一条毛巾顺序版的成本是二十四美元，是同步版七点四六美元的三倍多。而这一切对应的是一台机械臂在桌面上完成一个任务。

token 与成本这两列几乎同步变化，说明成本主要由 token 用量驱动；论文也说明费率取的是 Standard API 价格，并且把缓存命中的折扣算了进去。这意味着换一个更便宜的模型、或者用上批量与缓存策略，成本结构会整体平移——但论文报告的是这套默认配置下的账。

掷土豆那一行还揭示了一个口径问题。论文说明投掷动作平均在任务下发 13.9 分钟后完成，之后对轨迹的分析与验证约占所报 22.8 分钟的 40%。也就是说，这张表里的「22.8 分钟」有接近一半不是机器人在动，而是 agent 在复盘自己的动作。

还有一处更隐蔽的口径要留意：耗时与成本只统计成功试次，失败试次的开销没有进表。四对装配是 4/5，也就是说有一次失败的账没有算进 54.3 分钟与 27.41 美元里；折毛巾同步版是 3/5，有两次未计入。这样一来，更该问的问题是「一次成功多少钱」：把失败摊进去之后，单位成功成本会比表里更高，高多少取决于失败试次跑了多久才被判失败，而这一项论文没有给。

编辑部判断：这条路线把「能力」和「成本」分得很开——成功率那一侧看着接近可用，成本这一侧离部署还很远。论文自己也没有回避：结论一节把执行时间、推理成本与协同可变形操作的可靠性并列为仍需解决的问题。

这张表比主结果更能说明这条路线依赖什么。同一个任务上，一边是 5/5、九分钟出头，另一边是 0/5；同一个模型家族里换一个更小的型号，成功率就从满分掉到零。「不做任务训练」不等于「不依赖模型能力」——能力整块被转移到了 agent 那一侧。

还有一个细节：GPT-6 Astra 三档思考强度的成功率都是 5/5，耗时也都落在九分钟出头，中档与高档几乎一样。作者没有解释这个现象，但至少在这一个任务上，更强的推理档位没有换成更好的结果，成本也没有明显变化。

对照组里还藏着一个容易被忽略的变量：agent 软件版本。论文写明模型版本、原生档位设置与 agent 版本都在采集前记录，任务参考、机器人函数与试次预算在各配置之间共享。换句话说，表 2 比较的是「同一套机器人接口 + 不同 agent」，这正好是这条路线唯一需要控制的变量。

编辑部判断：这对做系统的人是一句很实际的话——这条路线能不能用，取决于 agent 侧模型的能力与价格，跟机器人本体的进展关系不大。它把具身系统的可行性绑定到了另一个迭代飞轮上。

放到 2026 年这个时间点上，这件事之所以值得讨论，是因为它依赖的三件能力刚好都成熟了：看懂多视角图像与深度、在运行期写出能跑的程序、在几十步的失败与重试里保持上下文。这三件事缺一件，agent 当策略都不成立。换句话说，这条路线能不能走，先看 agent 侧，再看机器人侧——这也是它与 VLA 路线在工程节奏上最大的不同。

八、经验复用：一个任务变快，一个任务没有

论文的第二个贡献是看「经验能不能攒」。两个任务各跑五次，每次都用新的 agent 上下文，从空经验开始，随后复用并更新保存下来的测量、步骤、修正与脚本——经验以文件形式存在工作区里，模型权重不变。

结果是两个任务给出两种走向：

  • 环形件拆装：第一轮之后明显变快，并维持在这个较低水平。
  • 两对装配：任务时间在起点附近来回波动，没有稳定下降；变短的主要是「写经验」这一步的耗时。

作者没有给出这两种走向差异的原因。本文只能照着写：在这两个任务上，经验复用一个有效、一个不明显。

「经验」在这里是一组具体的东西：量出来的几何尺寸、跑通过的步骤、踩过的修正、可以直接复用的脚本，全部以文件形式留在工作区，由新的 agent 上下文读取。每次执行开始时都是空经验，之后读写同一份目录；模型权重始终不变，变的只有这些文件。 这个设计的好处是它把「学到的东西」变成了可检查、可复制、也可以整包交给别人的产物——迁移实验就是这么做的。

跨模型迁移只做了一次：把 GPT-6 Astra 攒下的经验以只读方式交给 GPT-5.6 Terra，Terra 的成功率从空经验时的 1/5 升到 2/5，成功试次的完成时间更短、token 更少。论文自己补了一句限定——成功次数太少，结论强度有限。

只读这个设定值得留意。Terra 不能修改经验文件，所以它拿到的是一份冻结的二手经验，走完五次试次也不会把自己的发现写回去。这样做换来了干净的对照（唯一的变量是经验来源），代价是放弃了「小模型持续改进这份经验」的可能。论文没有讨论后一种设定。

这里还有一处对读者友好的诚实：论文把「时间从哪里算到哪里」写进了附录——环形件的交接、两对装配的试次内开销各有边界定义。不同统计边界下的曲线形状会不一样，这也是为什么本文只转述「一个变快、一个波动」这个方向，而不去比较两者的速度。

九、与相邻路线比较

把这条路放进 2026 年出现的几个位置里横向读：

工作把决策放在哪一层是否训练策略
VLA（π0.5 一类）学出来的策略：观测与指令直接映射到动作是
RoboICL部署期上下文适配，动作仍由学出来的生成器给出不更新参数
WAM决策是否显式包含动作后果通常是
RPent / Harness VLAagent 组织执行，冻结的 VLA 负责接触密集操作VLA 冻结，不新增训练

AGP 与上一篇的 RPent 放在一起看最有意思：两者都在同一个位置上放了一个 agent，但一个让 agent 去调度工具，另一个让 agent自己当工具的执行者。RPent 的 agent 需要一个 VLA 原语来完成接触密集操作；AGP 的 agent 靠写程序与位姿计算把动作直接算出来。

这两条线之间没有引用关系。AGP 的参考文献里没有 RPent，RPent 的官方资料里也没有 AGP——它们是同一个压力下的并行解：当模型已经能推理和写代码了，策略这一层还要不要单独训一个网络？

两条线的分工差异也可以用一句话说清：RPent 的 agent 需要知道「调用哪个工具、什么时候重试」，AGP 的 agent 需要知道「目标位姿是多少、这段程序写得对不对」。 前者把物理接触外包给一个冻结模型，后者把物理量算在自己手里。谁更稳、谁更便宜，取决于接触密集操作有多难，以及几何计算有多容易——论文没有给出这个分界线在哪。

十、它还没有回答什么

第一，没有与学习型策略的对照。 论文没有给出任何 VLA 或行为克隆方法在同一批任务、同一协议下的数字。因此「agent 直接当策略」相对「训练一个策略」的性价比，本文无法判断——这也是本篇最实质的缺口。

第二，样本量太小。 每组配置只有 2 到 5 次试次，没有统计显著性；经验迁移一节作者主动承认成功次数不足。

第三，失败模式没有系统报告。 现在只有成功数与个别描述（同步折叠最难、六块塔开销更大），看不到失败集中在哪一步、是否能恢复。

第四，成本口径与其他工作不可直接横比。 时间统计含动作复核与结果验证，只覆盖成功试次；换一个统计口径，数字会完全不同。

第五，准备环节的边界没有说清。 预定义初始场景有多少种、任务定义由准备 agent 写到什么程度，会影响「零样本」这个说法的强度。

第六，观察到的现象没有因果解释。 思考档位从低到高结果不变、经验复用在两个任务上走向相反、token 与耗时的关系在不同任务间并不一致——论文给出了现象，但没有给出机制。对做复现的人来说，这几处是最需要补实验的地方。

第七，任务定义的可迁移性没有被检验。 这套系统依赖一份提前写好的任务定义（目标、材料、约束、完成条件、预算）。换一批零件、换一个工作台、换一台机械臂之后，这份定义能复用到什么程度，决定了这套方法是「一个可复制的流程」还是「一组手调出来的场景」。

十一、青稞技术小结

把这篇工作压成一句话：它把「策略必须是训练产物」这个前提拿掉了，代价写在成本表里。

这条路线的意义在于把问题讲清楚了。当 agent 能读观测、能写程序、能按物理反馈改主意时，训练一个策略网络所能带来的收益，就从「能不能做」变成了「值不值得」。AGP 给出的是一个极端答案：完全不训，让 agent 在运行期算。它用 21 到 54 分钟、7 到 27 美元换来了七组不低于八成、五组满分的成绩。

和前面几篇放在一起看，这篇文章的价值还不止于它自己。它把「策略」从一件默认存在的东西变成了一件需要论证的东西：如果 agent 已经能算目标位姿、能在失败后改做法，那么继续投入训练一个策略网络，换回来的到底是什么？可能是速度、可能是成本、可能是分布外稳定性——但这些都需要在同一批任务、同一套预算下比出来，而目前没有人给出这样的对照。

真正需要观察的变量是成本曲线。成功率会随着 agent 模型迭代继续往上走，但只有单任务成本下降一个量级，这条路才会从「能跑通」变成「可以用」。在那之前，它更像一个探针：它测的不是机器人能做什么，而是「策略」这一层还剩多少必要性。

附：与系列文章的关系

第一篇讨论具身智能三阶段与数据、评测、世界模型等线索；第二篇讨论 VLA 主线的 action interface；第三篇讨论 RoboICL 的 adaptation interface；第四篇讨论 WAM 的 prediction / consequence interface；第五篇讨论 harness 的 execution-organization interface。这一篇讨论 policy-ownership interface：谁拥有发出动作这件事。

五个位置不是代际替代关系。动作怎么产生、适配发生在哪、后果如何进入决策、执行由谁组织、策略归谁所有，这五件事可以分别推进，也会互相借用实现——把 agent 当策略的系统同样可以用一个 VLA 来补它不擅长的接触密集环节，反过来也一样。
